# Versioned session case files — M1

`public/case-model.js` is the shared browser/Node validator. `advocacy-case`, schemaVersion1, max1,000,000 UTF-8 bytes, max60,000 characters per long text, max200 records per list (some individual fields are smaller). Unknown fields, unsupported versions/types, duplicate IDs, unsafe source URLs, embedded URL credentials, invalid calendar dates, missing date basis and dangling source references are rejected. There is no version migration yet; future versions need explicit migration tests.

The data model covers story and intake drafts, preferences, jurisdiction status, user reports/corrections, research/open questions, institutions, source records/passages/hash/dates, claim references, options/chosen approach, action owners/date classification/completion, notes/correspondence, unverified suggestions/pending suggestions, revision/review flags, evidence/strategy checks, unsubmitted source/action edits, current editing ID and view. Some research fields have no editor yet: JSON preserves them, readable exports include them, and no research/verification functionality is implied.

The legacy `state` facade points to the same canonical object. Input/change/submit/click capture updates the model; reading an export captures current rendered editing values first. Word and Markdown use the same captured case and existing DOCX generator. They are readable exports, not lossless restore formats. An original already-closed legacy session cannot be recovered; existing exported Markdown/Word is not automatically converted.

Restore parses a detached tree before replacement, asks for confirmation, cancels pending AI and does not restore consent/credentials/provider choice. There is no file upload, fetched source URL, executable HTML, storage, cookie or account. Rejected/cancelled imports leave case content untouched. Invalid source-editor drafts can be retained as text but submitted source URLs still require validation. Clearing replaces the whole case and rendered fields, and invalidates pending imports. It cannot erase device downloads, clipboard, extensions or browser backups.

Imported institutions/claims/options accept only unverified or needs-review statuses. Schema validation is not civic verification. Dates/quoted passages/check dates in an imported file remain user-supplied, not proof of official authority. Changed concern/goal/location marks generated conclusions and suggestions for review without destroying edits or completed actions.

Tests: `node tests/case-model.cjs` runs full-field roundtrip and24 schema checks; `npm test` includes this and five browser suites, including JSON close/reload/restore, unsaved buffers, cancellation, malformed/future/prototype/unsafe/oversize input, source editing and no provider consent restoration. Fixtures are synthetic.
